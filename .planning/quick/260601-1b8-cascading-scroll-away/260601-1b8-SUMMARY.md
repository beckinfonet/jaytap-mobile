## On-device QA checklist (iPhone + Android × light/dark × EN/RU)

Copied verbatim from `GSD-HANDOFF-cascading-scroll-away.md` § "On-device QA":

1. Open Home with `filterStyle = cascading`. Panel shows at top, count/summary line pinned below search.
2. **Scroll the results up** → the panel scrolls away with the list; search bar + summary row stay pinned; results get the full height. (This is the whole point — it must not stay fixed.)
3. While scrolled down, **tap the filter icon** → list scrolls to top AND the panel is visible (Task 3).
4. **Tap the summary row** → same as the filter icon (re-opens + scrolls to top).
5. Tap the filter icon again to **collapse** → panel unmounts, space reclaimed, summary row still shows the active filters.
6. Change deal / category / type → results + the summary breadcrumb update live (no Apply).
7. Switch to **Guided** style → unchanged (still a bottom-sheet modal).
8. Pull-to-refresh still works from the top.

## Gotchas / things to know

- **`useCallback` on `renderListHeader` is load-bearing.** Passing a freshly-created inline arrow to `ListHeaderComponent` remounts the header subtree on every parent render, which drops scroll position and can blur taps inside `<CascadingFilter>`. Keep the reference stable; the dep array must include every value the body reads (15 deps as of this commit).
- **Task 3 is the single most important on-device check.** Without `scrollToOffset({ offset: 0, … })` on expand, tapping the filter icon while scrolled down silently does nothing — the panel mounts above the viewport. QA Step 3 is the canary.
- **Why ` · ` (middle dot) and not `→` or `|`?** Mirrors the existing location title at HomeScreen.tsx L361 (`${country} • ${city}`). Same visual rhythm, no new design decisions.
- **Breadcrumb does not show "0 types".** When `types.length === 0`, `joinTypes` returns `''` and the empty fragment is filtered out before the `.join(' · ')` so the row reads `Rent · Residential` (deal · category only). Matches the Cascading panel's own breadcrumb collapse rule.
- **`liveCount` prop on CascadingFilter is still forward-fit/unused.** The summary row (and the old result-count line before it) is the visible count surface — that's intentional per Phase 14 UI-SPEC §"CascadingFilter anatomy" final note.
- **Pre-existing tsc errors (21 in 8 files).** All in unrelated files (`StepperInput.test.tsx`, `DeleteListingModal.tsx`, `Chat*Screen.tsx`, `ThemeContext.tsx`, etc.) — baseline preserved.
