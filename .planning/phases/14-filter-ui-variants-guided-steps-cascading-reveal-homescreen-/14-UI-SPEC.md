## Spacing Scale

Declared values (4-point base; multiples of 2 also permitted where handoff JSX uses half-steps — see Exceptions). All values land on a 2-point grid, with the canonical 4-point ladder being the primary scale.

| Token | Value | Usage in Phase 14 |
|-------|-------|-------------------|
| 2 | 2px | Stepper connector bar height; Cascading category-tab underline height (2.5 — see Exceptions); nesting-rail width |
| 4 | 4px | `hitSlop` value on all interactive elements (CONTEXT.md D-19); nesting-rail `left` offset |
| 6 | 6px | Nesting rail `top`/`bottom` inset (handoff filters-variants.jsx:201) |
| 8 | 8px | Stepper top padding; row gaps between stepper pill + label; small icon-to-text gaps |
| 10 | 10px | Multi-select chip gap; Type-card inner gap (icon → check → label); chip vertical padding |
| 12 | 12px | Body content gap (`gap: 12` between cards in Guided body); footer top padding (`12px 22px 26px`) |
| 14 | 14px | Type-card padding (handoff line 150 — `14px 14px`); type-card border-radius; chip left-padding |
| 16 | 16px | Big-card icon ↔ content gap; sheet body inter-card spacing on certain screens; primitive `gap` default |
| 18 | 18px | Big-card vertical padding (handoff line 117 — `18px 20px`); big-card border-radius; nested L2+L3 wrapper `paddingLeft` (Cascading); section gap |
| 20 | 20px | Big-card horizontal padding (handoff line 117) |
| 22 | 22px | Sheet body horizontal padding (handoff lines 97, 132, 162 — `22px`); Cascading category-tab inter-gap; sheet header horizontal padding |
| 24 | 24px | Card-row vertical rhythm minimum; close-button accessible diameter target |
| 26 | 26px | Stepper pill diameter (handoff line 104); footer bottom padding (`26px`) |
| 32 | 32px | Sheet `borderTopLeftRadius` + `borderTopRightRadius` (CONTEXT.md D-01 + handoff) |
| 48 | 48px | Big-card icon-chip diameter (handoff line 118) |

**Exceptions (intentional, documented):**

- **2.5px** — Cascading category-tab active underline height (handoff line 211; visual precision — 2pt reads too thin, 3pt reads heavy). Acceptable single-purpose deviation from the 4-point grid; one use site.
- **1.5px** — Big-card and Type-card active-state `borderWidth` (handoff lines 117, 150 — `1.5px solid`). Half-pixel border is standard practice on RN; one consistent value across the contract.
- **44pt minimum tap target** — Achieved on stepper pills (26pt pill + 4pt hitSlop on every edge + ≥9pt surrounding padding) and on the X close button (36pt visual + 4pt hitSlop). Validated against iOS HIG ≥44pt minimum.
- **13.5px** — Big-card blurb font size; breadcrumb font size; Cascading result-line detail font size (3 sites in handoff). Half-step justified for visual hierarchy: 13.5 is the visible rest-state between 13 (small dim) and 14 (body interactive). One consistent value.
- **11.5px** — Cascading section-header font size (`CATEGORY` / `TYPE` uppercase). Two sites; matches handoff line 204 + 219.
- **15.5px** — Cascading category-tab font size (handoff line 209). One site.
- **14.5px** — Cascading chip font size (handoff line 226). One site.

### Empty / edge-case states

### Error states

**Phase 14 has no error states.** No network calls, no async failure paths, no validation. The variants are pure controlled components reading from in-memory state.

### Destructive confirmations

**Phase 14 has no destructive actions.** No "Clear all" (deferred), no "Reset" affordance. Multi-select toggle is a non-destructive non-confirmed UI interaction. CONTEXT.md `<deferred>` rejects adding a Clear-all affordance for v1.

| Stepper pill color change | **No animation** — instant token swap on `step` state change | — | — | — | RESEARCH.md §Stepper Visual States (snap-swap; CSS `transition: all .2s` in handoff JSX translates to instant in RN unless explicitly animated; deferred polish) |
| Multi-select chip toggle | **No animation** — instant background/border swap | — | — | — | RESEARCH.md Pattern 2 (anti-pattern: do NOT add LayoutAnimation per chip — re-layouts whole panel) |
| Step body transition (Guided step 0 → 1 → 2) | **No animation** — content snap-swaps via `step === 0 && ...` conditional render | — | — | — | RESEARCH.md Anti-Patterns (mixing LayoutAnimation inside an Animated.View subtree is bug-prone) |

**Anti-patterns asserted (must NOT appear in implementation):**

1. **Do NOT call `LayoutAnimation.configureNext(...)` inside `togglePropertyType`** — re-layouts whole panel on every chip tap. Per-chip animation is jank surface. RESEARCH.md Pattern 2 explicit.
2. **Do NOT use `animationType="slide"` or `"fade"` on the Modal** — that's RN's built-in animation, conflicts with the hand-driven `Animated.Value` + `translateY`. Use `animationType="none"`. RESEARCH.md Anti-Patterns explicit.
3. **Do NOT omit the `localOpen` shadow state** — `visible={open}` directly unmounts the Modal instantly when `open → false`, so the slide-out animation never plays. RESEARCH.md Pattern 1 "load-bearing trick".
4. **Do NOT mix `LayoutAnimation` inside an `Animated.View` subtree** — both write to the same view tree; officially documented as "subject to bugs" per RN docs. Use cross-fade `Animated.View` for any step-transition polish if added in M7+. RESEARCH.md Anti-Patterns explicit.
5. **Do NOT add `keyboardVerticalOffset` anywhere in the sheet** — project-banned per KBD-02 (`m1-keyboard-kbd-02-invariants.md`). Sheet has no `TextInput`, so this should not tempt anyone, but the grep gate (`grep -rn "keyboardVerticalOffset" src/ | wc -l` MUST equal 0) is part of every plan's acceptance.

**Animation testing caveat (RESEARCH.md):** `react-test-renderer` does NOT execute Animated timing; `Animated.timing(...).start(cb)` fires the callback IMMEDIATELY in tests (RN auto-mocks). Plan 14-03 tests must not assert on intermediate animation frames — only initial state and final post-animation state. Document this in test file headers.
